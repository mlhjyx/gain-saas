# Top Tasks 与可用性验证计划（v3.0 ch07 / F2）

> 生命周期：`DRAFT`（执行前由产品负责人过目）
> 依据：`/home/xin/.claude/plans/gainos-plan-chapters/07-frontend-business-flow.md` 的 7.x Top Tasks 与可用性门；审计台账 §5.10（基线：任务成功率中位 78%、SEQ 5.5/7、SUS 68）。

## 1. 目的

用数据决定导航与页面去留（top tasks 通常 <10、常 <5），并为重构前后提供可对比的可用性基线。F2 出口判据：任务成功率、SUS/SEQ 基线建立；Top Tasks 清单冻结；树测试门通过。

## 2. 方法

1. **Domain Storytelling（2 场，各 60–90 分钟）**：参与者=1 名运营 + 2–3 名真实用户（design partner 或内部以真实任务扮演）；产出 as-is / to-be 故事图各 1 份，作为状态机与页面裁决输入。
2. **Top Tasks 投票**：候选任务 46 条（见 ch07 附录 A）× 每人 5 票；样本目标 ≥20；判定门槛：得票 ≥5%、进 top 8、长颈 50% 截断。
3. **树测试**：用目标 IA（6 导航 + /tasks + 回复 tab）做纯文本树，5 个找物任务；门限：直接命中率 ≥70%，首点击错误集中于单一分支则调整 IA。
4. **可用性测试 5 人 × 3 轮**：每轮 4 段任务脚本（找任务→看 run 结论→审批一次战役→从线索走到触达草稿）；记录任务成功率/用时/SEQ；每轮后修复 top3 问题再测。
5. **SUS 全量表**：每轮末做，样本 ≥8；与基线 68 对比。

## 3. 任务脚本（首轮）

| # | 任务 | 成功判据 |
|---|---|---|
| T1 | 找到最近一次挖掘任务，说出它判定多少家、匹配多少、为什么部分完成 | 30 秒内指出「最近任务摘要条」三个数字 |
| T2 | 从工作台出发创建一个新的挖掘任务并启动 | 3 次点击内到达 /tasks 或找买家发起 |
| T3 | 批准一个待审批战役，并说出批准后会发生什么 | 找到审批卡 + 影子期说明，勾选确认 |
| T4 | 给一个已接受线索建触达草稿（用联系人选择器） | 不手输 UUID，2 分钟内完成草稿保存 |
| T5 | 查看买家回复并判断是否需要跟进 | 在「回复」tab 找到分类与主题 |

## 4. 记录与产出

- 每场录制（经参与者同意）与笔记；结果写入 `docs/evidence/YYYY-MM-DD-usability-round-N.md`。
- 指标表：任务成功率、平均用时、SEQ、SUS、问题清单（编号/页面/严重度）。
- 本轮发现回流：F0/F1 台账新增条目 → 修复 → 下轮复测。

## 5. 排期与人员

- W1：Domain Storytelling×2；W2：Top Tasks 投票 + 树测试；W3–W4：3 轮可用性测试（每轮 5 人）。
- 执行：主会话组织；参与者由产品负责人协调（内部 3–5 人即可起步，无需外部招募）。
