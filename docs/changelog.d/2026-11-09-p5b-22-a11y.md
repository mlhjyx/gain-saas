- 起因：ch07 §7.5 P5b-22 —— 可访问性此前只有零散人工检查；没有 CI 门，AA 违规随迭代回潮。
- 改动：
  - `@axe-core/playwright` 进 devDependencies；新增 `apps/web/e2e/a11y.spec.ts`（WCAG-EM 抽样）：队列/公司/任务/通知/审计 5 类页面 + 接受对话框 + 新建公司向导 2 个流程，规则集固定 `wcag2a`+`wcag2aa`，任何新增违规 CI 红。
  - 审计口径：只扫业务内容区（`[data-layout-region="scroll"]`）与弹层（`[role="dialog"]`）；框架壳（侧栏菜单 listitem/aria-required-children、头部 UserDropdown/Notification 触发器 button-name、全局搜索 kbd 提示对比度、版本号对比度、工具栏折叠按钮）单列「框架 chrome 排除清单 + 已知违规登记」，留给框架升级跟进，不与业务修复混在一起。
  - 业务侧真修复：新建公司向导弹层补 `role="dialog"` + `aria-modal="true"`（此前只有 aria-label，屏幕阅读器不识别为模态）。
- 测试：a11y e2e 7/7（5 页面 + 2 流程）；既有 e2e 不受影响；build/lint 绿。
- 未做：框架 chrome 的 5 类违规修复（vben 升级项，清单在 spec 注释里）；移动端断点的抽样（P5b-21 人工走查覆盖）。
