## 4. 数据模型(SaaS 自有库,Prisma)

> 命名沿用引擎习惯(snake_case 表名)。个人数据红线:仅 `event_inbox` 及其派生表可能含个人数据(事件 envelope),按 SD5 管理,DSR 级联删除。

| 表 | 要点 |
| --- | --- |
| `user` | id、email 唯一、password_hash(argon2id)、status |
| `workspace` | id UUID(= 引擎租户 id,签发引擎 token 用)、name |
| `membership` | (user_id, workspace_id) 多对多(SD2);role: `admin`/`member`;status |
| `invitation` | workspace、email、role、token、过期、接受状态 |
| `ops_user` | 平台运营账号,**独立于 user 表**(独立登录域、独立 cookie);首个由 bootstrap 脚本创建 |
| `session` | jti、user_id/ops_user_id、realm、过期——支持登出与强制失效(PRD §2.3 短 TTL 的补充) |
| `workspace_registry` | 事件消费遍历的 workspace 清单(含启停)——worker 按此逐 workspace 拉取(引擎事件按 workspace 隔离,token 必带 workspace claim) |
| `event_inbox` | **event_id 主键(幂等)**、workspace_id、type、payload jsonb、occurred_at、acked_at;含个人数据,DSR 级联 |
| `qualified_lead` | `LeadQualified` 派生的只读投影(界面列表用);可由事件重放重建 |
| `notification` | user/workspace、type、ref、read_at;站内通知中心数据源 |
| `audit_log` | actor(realm+id)、action、target、detail jsonb、at;控制面 + 运营域白名单写全量 |
| `feedback_submission` | 周报在线反馈:workspace、icp、ISO week、行数据、引擎返回的接受/拒绝计数(SD8 对账) |
| `deletion_mirror` | DSR 转发记录:引擎 deletion_request id、状态、SaaS 侧级联删除计数 |
| `cost_ledger` | workspace、来源事件、金额、at(SD3:为二期 billing 归因积累) |
| `signing_key` | kid、算法、状态(active/previous)、创建时间;私钥本体在 env,库里只存元数据(双钥轮换 SD/§2.3) |

迁移:Prisma Migrate,迁移文件入仓;带迁移窗口先 `pg_dump`(沿用引擎惯例)。

## 5. 鉴权与会话

三个登录域,三套 guard 链,cookie 名互不相同:

1. **租户域**:邮箱密码(argon2id 校验)→ 会话 JWT(HS256,httpOnly `SameSite=Lax` cookie,60 分钟滑动刷新)→ `TenantGuard`(membership 校验 + 角色注入请求上下文)。CSRF:`SameSite=Lax` + 自定义头校验双保险;登录接口限流。
2. **运营域**:`ops_user` 独立登录,独立 cookie 与 `OpsGuard`;无 workspace 概念,无引擎 scope。
3. **引擎 token 签发(服务域,BFF 内部)**:按请求铸造 RS256 JWT,claims `sub`(用户 id)/`workspace`(UUID)/`roles`(按 membership 角色映射 `saas-admin`/`saas-member`),TTL ≤ 60s(不缓存或极短缓存);角色→引擎 scope 的映射由引擎侧 `AUTH_ROLE_SCOPE_MAP_JSON` 配置(SD 表见 PRD §2.2)。JWKS 端点 `/.well-known/jwks.json`,kid 双钥重叠轮换。
4. **事件消费服务身份**:worker 专用,`roles: ["saas-event-consumer"]`,按 `workspace_registry` 逐 workspace 铸 token(引擎强制 workspace claim);引擎侧映射授予 `acquisition:read + personal-data:read + acquisition:event:ack`(SD4/SD5)。

## 6. BFF(SD7 铁律的工程化)

- **路由表驱动**:租户域路由模块逐条声明 SaaS 路径 → 引擎客户端调用;新增透传只加一行路由,不写逻辑。
- **错误映射中间件**:引擎错误(status + code)→ `packages/shared` 三层文案表(§14.2/§14.4)→ 统一 envelope;「技术详情」(原错误码、trace、请求 id)附在响应的 `meta` 字段,前端折叠展示。
- **横切**:per-user/workspace 限流(nestjs throttler)、变更类请求审计、`Idempotency-Key` 原样透传(引擎支持幂等键);同步模型生成路由(ICP/查询计划/接触草稿)单独 240s 超时,其余 30s,避免模型生成期间被 BFF 提前掐断。
- **引擎客户端生成**:`pnpm gen:engine` 拉引擎 OpenAPI JSON 生成到 `packages/engine-client`;CI 校验生成物无漂移——引擎合同变了,不重新生成就编不过。

### 6.1 内嵌模型网关(运营台配置 AI)

- **运行面**:`POST /v1/chat/completions`、`GET /v1/models`,只接受 `MODEL_GATEWAY_API_KEY` Bearer;引擎 `MODEL_GATEWAY_URL` 指向 `http://127.0.0.1:4020/v1`(host network,loopback)。
- **数据**:`ai_provider`(厂商 Base URL/Key 密文/优先级/超时)、`ai_model_route`(引擎请求别名→上游模型,多厂商回退 + 默认路由)、`model_call_log`(元数据/token/延迟/错误,不含 prompt)。运营只选预制厂商、填 Key、测试自动拉模型并选默认模型;系统自动建 `default` 路由兜底所有引擎任务,别名路由只在高级区出现。
- **管理面**:`/api/ops/model-gateway/**`,OpsGuard + 全量审计;Key 只显示掩码。
- **站点构建 settlement 兼容**:客户 worker 启动/心跳硬性检查 new-api settlement readback。gain-saas 本地应答 `/api/settlement-readback/v1/capability`,其余读回请求与带 `X-New-API-Settlement-*` 的模型调用(含 `/responses`、`/messages`、`/embeddings`)透明代理到 new-api;获客模型调用仍走本地厂商路由。详见 `deploy/model-gateway.md` §3.2。

## 7. 事件消费 worker(SD4 落地)

```text
每 2 分钟(@nestjs/schedule)+ accept 后即时触发:
  for ws in workspace_registry(启用):
    loop: GET /events?cursor={ws.cursor}&limit=100
      → 逐条 upsert event_inbox(按 event_id 幂等;冲突即跳过)
      → 派生:LeadQualified→qualified_lead;终态事件→notification;成本事件→cost_ledger
      → 更新 ws.cursor
      → ACK 批:POST /events/ack(失败只重试 ACK,不重拉)
对账:每日抽样 GET /events/:eventId/ack-status(404≠未消费,仅 ACKED 确认)
启动:首次运行先回放存量(引擎 279 条 PENDING,含 11 条 LeadQualified)→ PRD G4 存量验证
```

DSR 级联:引擎删除请求完成 → worker 删除 `event_inbox`/派生表中对应 workspace/主体记录并写 `deletion_mirror` 留痕(§4.2 A6)。

## 8. 前端架构(vben)

- **变体与集成**:取 vben 5 的 `apps/web-antd`(Ant Design Vue)与其依赖的 internal packages,拷入 `apps/web` + `packages/vben`,**去掉 turbo**,并入本仓 pnpm workspace;`packages/vben/VENDOR.md` 记录上游 commit,锁定不追升级(安全修复手动 cherry-pick)。
- **两个路由组**:`/tenant/*`(admin/member,主链路六导航,PRD §14.1)与 `/ops/*`(operator,新运营台);vben 路由级权限按角色生成;两组不同布局与菜单源,登录按账号域分流(§5),互不可达(负向测试 E1)。
- **§14 落地映射**:六步进度条 = antdv Steps 封装为全局组件(工作台/找买家/买家线索页顶);通知中心 = antdv Badge+Notification + 轮询 `/notifications`;骨架屏/空状态/三层错误(读响应 `meta` 折叠)做全局约定组件;在线周报反馈 = 列出 `QUALIFIED` 线索逐条提交 `outcomes`(追加留痕),精确 ISO 周仍用导出 CSV 原样回填上传(SD8)。
- **文案**:全部经 `packages/shared` 的术语与文案表;禁止界面硬编码引擎术语(走查 = PRD F2)。
- **构建与托管**:vite build → Nest 静态托管 + SPA fallback(单进程单单元);开发期 vben dev server 代理到 `127.0.0.1:4020`。
- **运营台 UI 重写原则**(SD9 修订):不移植旧中台 React 页面;新界面按 §14 同等标准面向运营——中文业务用语、就绪状态红绿灯、危险操作(Kill Switch/schedule trigger/源删除)二次确认、诊断页"发生了什么/怎么办";服务端数据面不变(§9)。

## 9. 运营域服务端(中台资产照搬)

- `packages/ops-pg` 原样移植:白名单语句注册表(新增写 SQL 必须登记)、fail-closed schema 探针(启动校验表/列,漂移即写端点拒绝)、`app_user`/`owner` 双连接池、租户表 RLS `set_config` helper——**这是安全边界,功能测试与负向测试(E4)随包移植**。
- Nest `ops/` 控制器:providers(Kill Switch)、sources(CRUD/立即抓取/fetches)、schedules(Temporal pause/unpause/trigger/CRUD)、budget(只读)、诊断(runs/leads/changes/fetches/traces 只读)、导出 CSV、审计查询。
- Outbox 诊断**不直写不重试**:读 SaaS 自有 `event_inbox` + 引擎 `GET /events/:eventId/ack-status`(SD9:手动 retry 已被消费自动化取代)。
- 首个 operator:`pnpm bootstrap:operator` CLI 创建。
