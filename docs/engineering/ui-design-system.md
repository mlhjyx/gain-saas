# 界面设计系统（Ant Design 基线 · 企业级）

> 2026-11-23 起生效。所有登录后业务页面（`/ops`、登录/注册/异常页除外）以本文为准；
> 色值来源仍是 [token-mapping.md](../evidence/ui-restyle/token-mapping.md) 与 `apps/web/src/app.vue` 的 `GS_BRAND`。
> 视觉目标：成熟、稳定、可长期维护的企业级数据平台（参考腾道一类 B2B 数据系统），不追逐装饰性潮流。

## 1. 唯一实现路径

- 交互组件一律使用 **ant-design-vue 4.x**（Button/Input/Select/Form/Table/Modal/Drawer/Tabs/Steps/Alert/Tag/Empty/Skeleton…）。
- 页面不允许再新增自定义按钮/输入/表格/弹层类；确需组合时使用 `components/gainos/ui/` 下的 `Gs*` 薄封装（GsPage / GsCard / GsToolbar / GsSegmented / GsTable / GsEmpty / GsModal / GsTag / GsStat / GsSelect / GsRadar / GsStatusIcon）。
- 封装内部必须 `import { Card, Tag, Empty, Modal, Table, Statistic } from 'ant-design-vue'` 后用 PascalCase 组件；**禁止写 `<a-card>`/`<a-tag>` 字符串标签**——本应用没有全局注册 AntDV，字符串标签会渲染成无样式自定义元素（卡片 0 padding、标题/标签丢失）。
- 页面级 `<style scoped>` 目标为 0 行；布局用 `a-row/a-col/a-space/a-flex`，视觉全部来自 token。
- 主题唯一来源：`app.vue` 的 `ConfigProvider`（`GS_BRAND` + `componentTokens`）。禁止在页面里写 `.ant-* { … !important }`。
- **antdv ≠ antd（React）**：按 Vue 版的 API 写。`Dropdown` 没有 `menu` 属性，菜单必须走 `#overlay` 插槽 + `<Menu :items @click>`
  （传 `:menu` 不报错，但会弹出一个空层，表现为「点了没反应」）。`MenuInfo` 类型未导出，用 `Parameters<MenuProps['onClick']>[0]` 取。
- **Cascade layer 陷阱**：Tailwind v4 的工具类在 `@layer` 里，antd 的 cssinjs 样式不在——同一个属性上 antd 永远赢。
  所以宽度、外边距这类布局工具类要写在**普通 div** 上，不要直接挂在 antd 组件根节点
  （实例：`-mt-12` 挂在 `a-card` 上被 `.ant-card{margin:0}` 吃掉；`w-[240px]` 挂在带 prefix 的 `a-input` 上被 `.ant-input-affix-wrapper{width:100%}` 吃掉）。
- 反馈（成功/失败提示、确认框、顶部通知）一律走 `apps/web/src/feedback.ts`（`App.useApp()` 上下文），不使用静态 `message/notification/Modal.confirm`，不使用 `window.confirm/alert`。

## 3. 间距与布局

- 间距刻度：4 / 8 / 12 / 16 / 24 / 32（`--gs-space-*`）。
- 页面：内容区左右 `--gs-page-pad`（clamp 20–32px，桌面 32px），最大宽度 `--gs-page-max`（1280px）；列表页卡片间距 12px，详情页 16px。
- **渐变页头**（`GsPage` 默认形态）：通栏 `--gs-hero-tint → --gs-hero-tint-soft → 透明` 的品牌蓝极浅渐变 + 右侧装饰插画（内联 SVG，颜色走 `--gs-hero-*`）；
  页头底部预留 64px 淡出区，**紧随其后的第一块面板包一层普通 div `-mt-12 relative z-[1]` 上移压进渐变**。设置类页面用 `:hero="false"`。
- 画布：`--background-deep` = `220 30% 97.6%`（近白微蓝），比纯灰更轻，白卡靠「环 + 投影」分层；暗色画布 `0 0% 7%`，暗色侧栏 `0 0% 12%`（纯中性，覆盖 Vben 自带的蓝调值）。
- 栅格：12 列；桌面卡片最小宽度 280px；窄屏单列。

## 4. 圆角与边框

- 全部 10px（按钮/输入/卡片/弹窗/下拉）；头像与圆形图标除外；药丸页签 8px。
- **卡片不画线边框**：`GsCard` = 白底 + 1px 环（rgba 3.5%）+ 柔和投影（`--gs-shadow-float`），10px 圆角；表单输入、弹窗仍用 1px `--gs-border`；分割线 `--gs-divider`。
- 阴影只用 float（卡片/工具栏）、xs、modal 三档；页头插画允许一层品牌色 drop-shadow，不使用其它彩色光晕。

## 5. 色彩

- 主色：#335CFF（hover #3559E9）；语义色：success #1A7544、warning #B75310、error #D02533。
- 中性灰阶：文字 #171717 / #5C5C5C / #7B7B7B；背景 #FFFFFF / #F7F7F7 / #F5F5F5。
- **状态色只允许出现在 Tag、Alert、趋势数字**；其余界面保持中性。
- 深色主题同结构，值见 `GS_BRAND.dark`。

## 6. 表格（企业级数据页的核心）

- `GsTable`：`size="middle"`，表头 12/500 + `--gs-table-head` 底，行高 48，hover 浅灰，无外框。
- 首列为主信息（公司/线索名，14/500）；数字列右对齐 + tabular-nums；状态列用 `GsTag`。
- 空态统一 `GsEmpty`；加载统一 `a-skeleton`；分页默认 20/页，超过 50 条显示总数。

## 7. 表单

- label 上置（12/500），控件高 40，错误 12px 语义红（`a-form-item` 自带）。
- 同一行最多 2 个控件；主提交与次操作分列右侧（Modal 页脚右对齐）。

## 8. 反馈与弹层

- 成功：`feedback.message.success`（3s 自动消失）。
- 可恢复失败：`feedback.message.error`；页面级持久错误：`ErrorNotice`（a-alert，保留「发生了什么/为什么/怎么办 + 技术详情」三层）。
- 确认：`feedback.modal.confirm`；行内危险操作 `a-popconfirm`。
- 顶部通知：`feedback.notification.*`（暗色自动取 token）。
- Modal：10px 圆角，页脚右对齐「取消 / 确认」，危险操作用 `danger`。

## 9. 动效

- ≤150ms，只动颜色/透明度/阴影；禁止位移、缩放、弹跳。
- 加载态用骨架屏；列表进入不加动画。

## 10. 可访问性与测试锚点

- 保留语义：H1/H2 层级、`role=dialog/alert/status`、`role=tab` 顺序与文案、`aria-pressed`、`<main>`。
- 测试锚点统一 `data-gs="<area>"`（如 `data-gs="lead-card"`、`data-gs="queue-toolbar"`）；
  旧的 `.wk__*/.ld__*/.cp__*` 等页面类名不保留。
- 错误三层块必须保留 `.error-notice__details summary` 的「技术详情」折叠（既有 spec 依赖）。

## 11. 判定结果（C1–C5）的展示契约（2026-11-23）

引擎把五维评分写成一段聚合文本（`judge-aggregate/v1：verdict=…，reasonCodes=…` + `C1_MATERIAL pass（score 8）：…`）。
**这段原文只能进「技术详情」，租户界面一律渲染解析后的业务语言。**

- 解析：`apps/web/src/views/leads/judge.ts`（`parseJudge`）。维度顺序 C1→C5，分数 0–10，`null`=证据不足；
  兼容字符串、字符串数组、JSON 字符串与对象包装；解析失败时退回「机器结论 + 人话理由」。
- 文案：维度名 `gainos.leads.criteria.*`（产品品类 / 买家角色 / 生产工艺 / 经营模式 / 企业规模），
  状态走 `@gain-saas/shared` 的词表（符合 / 偏弱 / 不符 / 证据不足 / 不适用）。
  模型理由里的 `ICP` 用 `humanizeRationale()` 换成「目标客户画像」。
- 列表卡（`views/leads/lead-card.vue`）：公司（首字母牌位 + 国家/域名 + 行业/规模）→ 评分（分数 + 分档）
  → 判断结果/原因（决定性维度的一句话）→ 五维摘要（图标 + 结论 + 分数）→ 操作（值得跟进/暂不跟进/⋯）。
  「待我判断」的卡片用 3px 左侧强调条；展开后显示逐维理由，机器码只出现在折叠的「技术详情」。
- 详情（`views/leads/detail.vue`）：判断结果 hero（总分 + 分档 + 状态 + 维度计数 + 关键理由 + 核心证据）
  + 五维雷达（`GsRadar`，纯 SVG）+ 逐维明细（状态、0–10 分条、理由）。
  证据不足的维度按 0 绘制并在图下注明；`scores` 的八维明细作为补充卡片保留。
- 红线：`C1_MATERIAL`、`reasonCodes`、`judge-aggregate`、裸枚举不得出现在可见文本中
  （`leads-judge.spec.ts` 用真实形状的数据锁定）。

## 12. 渐变页头、药丸页签与名录卡片（2026-11-24，参考商业名录页）

### 12.1 页头与步骤面板
- `GsPage`：H1 28/600 + 副标题 13px；无 `#actions` 时右侧画装饰插画，有操作按钮时不画（避免重叠）。
- 主链路步骤条用共用的 `GsSteps`，放进白色薄面板（`GsCard dense`，body 12px 24px），上移压在页头渐变上；**页面里不要直接用 antd `Steps`**。
- **步骤条不显示序号**（用户不知道「5」指什么）：已完成的步骤是对勾，当前步是「蓝底圆 + 白点」，还没走到的步骤是空心圆。
  antdv 给 item 传了自定义 icon 就会取消默认蓝底圆（`ant-steps-item-custom`），圆底由组件自己画。
- 步骤条只是进度指示：antd 会把每一步渲染成可聚焦的「按钮」而点击无效，`GsSteps` 已去掉这层语义。

### 12.2 药丸页签（`GsSegmented`）
- 文字项 13/500 + 计数；选中项 = `--gs-accent-soft` 浅蓝药丸 + `--gs-accent-fg` 文字，无下划线。
- antdv 4.2.6 的 `Segmented` 选中态固定是「灰轨道 + 白滑块」且不可令牌化，`Tabs`/`Radio.Group` 也没有这个形态，所以它是设计系统自有的最小原语：
  `role="group"` + 一组 `aria-pressed` 的 toggle button，Tab 逐个聚焦、Enter/Space 触发。

### 12.3 工具栏
- `GsToolbar`：白色浮起面板，padding 8px 12px 8px 8px；左侧页签、右侧「目标客户画像下拉 / 搜索 / 页面操作」。
- 带放大镜前缀的搜索框必须包一层定宽 div（见 §1 的 layer 陷阱）。

### 12.4 线索卡（`views/leads/lead-card.vue`）
- 五列：公司（56px 首字母色块 + 名称 15/600 + 定位行 + 行业/规模标签）→ 评分（28/600 + 线索评分 + 分档药丸）→
  判断结果（结论药丸 + 一行原因 + 展开收起）→ 判定维度（图标 + 名称 + 结论 + 0–10 分）→ 操作（跟进 / 排除 / ⋯，垂直居中）。
- 结论药丸 = **机器结论**（值得跟进 / 偏弱 / 不建议跟进 / 待评估），不是队列名；队列由当前页签表达，卡片内不再重复。
- 按钮文案与队列名对齐：「跟进」→ 已移入「值得跟进」，「排除」→ 已移入「已排除」（i18n `leads.cardAccept` / `leads.cardReject`）。
- 折叠态只留一行原因，维度计数摘要和逐维理由在展开区。
- 断点：内容区 ≥ ~1200px（视口 ≥ 1512px）五列并排；以下四列 + 判定维度横排到底部；手机单列。

### 12.5 没有数据、不做假的部分
公司 logo 用首字母色块（接口无图）；「已核验」对勾、评分涨跌箭头、「解锁积分」在参考图里有，但本产品没有对应数据，一律不画。

## 13. 决策人列表（线索档案包 →「决策人」页签，2026-11-25）

- 页头：H2「决策人」+ 说明 + 右侧操作（猜测邮箱 / 发现联系人），直接落在画布上，不套卡片。
- 每位决策人一张 `GsCard`（padding 18px 24px），内部**三列网格**：人（头像 + 姓名 15/600 + 职位·部门 + 级别标签）/
  联系方式 / 来源。内容区 < ~1200px 时来源落到卡片底部；手机单列。
- 联系方式每行 = 等宽类型标签（邮箱 / 电话 / LinkedIn，68px）+ 值 + 状态药丸 + 日期位（常驻 80px，保证药丸上下对齐）+ 「验证邮箱」。
- 状态药丸只给业务词（`contacts.badge.*`：已验证 / 待确认 / 推断 / 已拦截 / 无效 / 未验证），
  不再带括号里的引擎枚举；语义：已验证=绿、待确认/推断=琥珀、已拦截=红、其余中性。
- 来源：同一层级有带链接的来源时，不再重复显示不带链接的同层级行；不同链接全部保留。
- 弹层用 antd `Modal`（不要自制遮罩层）；待确认/推断邮箱必须勾选确认项才能继续。
- **三列网格必须挂在卡片内容的内层 div 上**：antd Card 会把插槽再包一层 `.ant-card-body`，网格写在卡片根节点上不生效。

## 14. 找买家页（目标客户画像 + 寻源方案，2026-11-25）

与买家线索页同一套「列表 → 详情」的结构，业务逻辑不变。

### 14.1 列表
- 页头、步骤条（`GsSteps`，有生效画像时停在第 3 步，否则第 2 步）、工具栏（标题 + 生效提示 / 刷新 / 设定目标客户画像）。
- 画像卡（`views/find-buyers/icp-card.vue`）五列：画像（首字母色块 + 名称 + 公司 · 版本 + 状态药丸 + 规则数 / 买家画像数）/
  目标市场 / 寻源方案 / 最近寻源 / 操作（查看与调整）。
- 「寻源方案」「最近寻源」进入页面时按画像并行预取：取不到显示「—」，确实没有才显示「还没有」——
  不把「没取到」显示成「还没有」。预取不阻塞列表。
- 断点：视口 ≥ 1408px 五列并排（五列最少约 1070px 内容宽度）；以下两行（画像 + 操作 / 目标市场 + 寻源方案 / 最近寻源）；手机单列。

### 14.2 详情
- 右侧抽屉（`min(920px, 100vw)`）：路由约定不允许新增页面，所以用抽屉承载「详情页」。
  页头 = 眉题 + 名称 + 状态药丸 + 公司 · 版本，右侧是「激活 / 编辑」。
- 正文按卡片分区：画像概览 / 反馈建议 / 寻源方案 / 最近寻源 / 高级：资格规则与回测（默认收起）。
  原始查询 JSON、规则表达式这类技术内容只出现在折叠区或「高级」里。
- 方案盒里的折叠头用 `expand-icon-position="end"`，并用 `:deep()` 归零 antd 的横向内边距，让它贴齐盒子。

### 14.3 弹层与提示
- 新建 / 编辑 / 规则都是 antd `Modal`；操作结果走 `feedback.message`，不再在页面里挂固定提示条。
- 新建时选择公司档案只显示名称——公司状态没有业务词表，不显示原始枚举。

## 15. 响应式（2026-11-25）

### 15.1 三种导航形态
| 视口宽度 | 导航 | 内容区宽度 |
|---|---|---|
| < 768px（手机） | 左侧抽屉（汉堡按钮打开） | 视口 − 页边距 |
| 768–1023px（平板竖屏） | 侧栏自动收成图标窄栏（60px），可手动展开 | 视口 − 60 − 页边距 |
| ≥ 1024px | 按用户的展开/折叠偏好 | 视口 − 224 − 页边距（展开时） |

- 手机抽屉与桌面侧栏是同一份内容（`sdr-nav-panel.vue`）：分组导航 + 通知 / 设置 / 帮助 + 带退出登录的账号卡；
  抽屉品牌行额外放主题 / 语言切换（手机上原本没有入口）。
- 平板自动收起不改动用户的真实偏好：自动收起时在本地留标记，离开这个宽度时恢复（刷新过也恢复）；
  用户在平板宽度下手动展开视为明确选择，不再恢复（`layouts/basic.vue`）。

### 15.2 布局断点按内容区宽度，不按视口
侧栏展开 / 收起 / 变成抽屉都会改变内容区宽度，按视口设断点会在平板上排错（实测 224px 侧栏下 596px 的内容区按 820px 排版，右侧整列被裁掉）。

- 页面根节点统一写 `grid-cols-1 @container`：`grid-cols-1` 约束列宽（子内容再宽也不会把整列撑出屏幕），`@container` 让后代可以按内容区宽度查询。
- 组件样式窄屏优先，用 `@container (min-width: …)` 逐级变宽；模板里的工具类用 `@min-[…]:` / `@max-[…]:`。
- **不要按视口写断点**（`@media (max-width)`、`lg:` / `md:`），除非元素在 Teleport 出来的弹层里（弹层不在容器内，只能按视口）。
- 页面根加了 `@container` 后会成为 `position: fixed` 后代的包含块，所以页面内不要直接放 fixed 元素，弹层一律用 antd（Teleport 到 body）。

### 15.3 各组件的分档（数值是内容区宽度）
| 组件 | < 520 / 560 | 中档 | 最宽档 |
|---|---|---|---|
| 线索卡 `lead-card` | 单列堆叠 | ≥ 520 两列（评分 / 判断结果）；≥ 810 四列 + 维度横排 | ≥ 1180 五列 |
| 画像卡 `icp-card` | 单列堆叠（< 560） | ≥ 560 两列 | ≥ 1120 五列 |
| 决策人卡 | 三段竖排（< 860） | — | ≥ 860 三列对齐 |
| 线索详情网格 | 单列 | ≥ 760 两列；≥ 900 结论 + 雷达并排 | — |
| 主链路步骤条 `GsSteps` | 竖排（< 760，组件自己量容器） | — | 横排 |
| 工具栏 | ≥ 两个控件时各占一半宽，两两成行（< 640） | 自动换行 | 同行 |

- 窄屏优先意味着每档的最小宽度都算上卡片内边距（24×2）；新增卡片时先写堆叠形态，再往上加档。
- 图表（雷达图）限定最大宽度并居中，不要跟着单列堆叠的卡片拉满。

## 16. 公司档案：主档案 + 关联公司（2026-11-25）

### 16.1 产品口径
- 引擎/PRD（`phase-1-01-04` §2）允许**一个工作空间多份公司档案**（集团/多品牌），每份独立维护 Claim/Offering/ICP；
  引擎侧没有「主档案」概念，只有 BFF 的 `Workspace.onboardingCompanyId` 记录注册时填写的那家公司。
- 产品层因此显式引入「主档案」：**注册公司永远是主档案**，日常操作与寻源以它为准；其他档案收在「关联公司」，
  添加前必须说明用途（集团/多品牌），避免用户把它当成「随便再建几家公司」。
- 老工作空间没有 onboarding 记录时，回退到创建时间最早的一份，徽标显示「主档案」（不谎称注册公司）。

### 16.2 页面结构
- 页头（`GsPage` 渐变）+ 主档案卡：
  - 身份：首字母方块 + 公司名 + 「注册公司」徽标 + 状态药丸 + 官网/行业/目标市场；
  - KPI：已通过事实 / 待确认事实 / 产品服务 / 待处理冲突（`/companies/:id/completeness`，并行预取）；
  - 「下一步」：按状态与事实进度只给一个明确动作（补全 → 确认事实 → 处理冲突 → 设定目标客户画像），
    不再让用户自己在一排按钮里找；
  - 页脚：企业事实 / 资料库 / 编辑（仅 DRAFT）/ 更多（市场候选、重试理解、确认档案）+ 目标客户画像摘要（组数、生效中）。
- 关联公司：仅在存在其他档案时出现；每张卡显示状态、行业/市场、画像摘要与主操作；搜索/筛选只在关联档案 > 3 时出现。
- 「添加关联公司」是次级操作，先弹说明再进入建档。

### 16.3 与下游的衔接
- 「找买家 → 设定目标客户画像」的公司选择器把主档案排在第一位并标注「（注册公司）」，避免选错公司导致寻源偏差。
- 公司页在从其他页签返回（keep-alive 激活）时刷新画像与事实计数。

### 16.4 弹层
- 建档、编辑、添加关联公司说明用 antd `Modal`；企业事实、资料库改用 antd `Modal` 外壳（`:footer="null"`、body padding 0），
  内容与业务逻辑不变；事实/资料库内部按钮逐步换成 antd `Button`。
