# 界面设计系统（Ant Design 基线 · 企业级）

> 2026-11-23 起生效。所有登录后业务页面（`/ops`、登录/注册/异常页除外）以本文为准；
> 色值来源仍是 [token-mapping.md](../evidence/ui-restyle/token-mapping.md) 与 `apps/web/src/app.vue` 的 `GS_BRAND`。
> 视觉目标：成熟、稳定、可长期维护的企业级数据平台（参考腾道一类 B2B 数据系统），不追逐装饰性潮流。

## 1. 唯一实现路径

- 交互组件一律使用 **ant-design-vue 4.x**（Button/Input/Select/Form/Table/Modal/Drawer/Tabs/Steps/Alert/Tag/Empty/Skeleton…）。
- 页面不允许再新增自定义按钮/输入/表格/弹层类；确需组合时使用 `components/gainos/ui/` 下的 `Gs*` 薄封装（GsPage / GsCard / GsToolbar / GsSegmented / GsTable / GsEmpty / GsModal / GsTag / GsStat / GsSelect / GsRadar / GsStatusIcon）。
- 封装内部必须 `import { Card, Tag, Empty, Modal, Table, Statistic } from 'ant-design-vue'` 后用 PascalCase 组件；**禁止写 `<a-card>`/`<a-tag>` 字符串标签**——本应用没有全局注册 AntDV，字符串标签会渲染成无样式自定义元素（卡片 0 padding、标题/标签丢失）。
- 页面级 `<style scoped>` 目标为 0 行；布局用 `a-row/a-col/a-space/a-flex`，视觉全部来自 token。
- 主题唯一来源：`app.vue` 的 `ConfigProvider`（`GS_BRAND` + `componentTokens`）。禁止在页面里写 `.ant-* { … !important }`。
- **antdv ≠ antd（React）**：按 Vue 版的 API 写。`Dropdown` 没有 `menu` 属性，菜单必须走 `#overlay` 插槽 + `<Menu :items @click>`
  （传 `:menu` 不报错，但会弹出一个空层，表现为「点了没反应」）。`MenuInfo` 类型未导出，用 `Parameters<MenuProps['onClick']>[0]` 取。
- **Cascade layer 陷阱**：Tailwind v4 的工具类在 `@layer` 里，antd 的 cssinjs 样式不在——同一个属性上 antd 永远赢。
  所以宽度、外边距这类布局工具类要写在**普通 div** 上，不要直接挂在 antd 组件根节点
  （实例：`-mt-12` 挂在 `a-card` 上被 `.ant-card{margin:0}` 吃掉；`w-[240px]` 挂在带 prefix 的 `a-input` 上被 `.ant-input-affix-wrapper{width:100%}` 吃掉）。
- 反馈（成功/失败提示、确认框、顶部通知）一律走 `apps/web/src/feedback.ts`（`App.useApp()` 上下文），不使用静态 `message/notification/Modal.confirm`，不使用 `window.confirm/alert`。

## 2. 字阶

| 用途 | 字号 | 字重 | 说明 |
|---|---|---|---|
| 页面标题 H1 | 28px（渐变页头）/ 20px（素净页头） | 600 | 一屏一个，位于 `GsPage` |
| 分区标题 | 16px | 600 | 卡片组/区块标题 |
| 正文与控件 | 14px | 400 | antd `fontSize` 默认 |
| 表格正文 | 13px | 400 | `GsTable` 默认 |

| 数字 | 14px | 500 | `font-variant-numeric: tabular-nums`，右对齐 |

## 3. 间距与布局

- 间距刻度：4 / 8 / 12 / 16 / 24 / 32（`--gs-space-*`）。
- 页面：内容区左右 `--gs-page-pad`（clamp 20–32px，桌面 32px），最大宽度 `--gs-page-max`（1280px）；列表页卡片间距 12px，详情页 16px。
- **渐变页头**（`GsPage` 默认形态）：通栏 `--gs-hero-tint → --gs-hero-tint-soft → 透明` 的品牌蓝极浅渐变 + 右侧装饰插画（内联 SVG，颜色走 `--gs-hero-*`）；
  页头底部预留 64px 淡出区，**紧随其后的第一块面板包一层普通 div `-mt-12 relative z-[1]` 上移压进渐变**。设置类页面用 `:hero="false"`。
- 画布：`--background-deep` = `220 30% 97.6%`（近白微蓝），比纯灰更轻，白卡靠「环 + 投影」分层；暗色画布 `0 0% 7%`，暗色侧栏 `0 0% 12%`（纯中性，覆盖 Vben 自带的蓝调值）。
- 栅格：12 列；桌面卡片最小宽度 280px；窄屏单列。

## 4. 圆角与边框

- 全部 10px（按钮/输入/卡片/弹窗/下拉）；头像与圆形图标除外；药丸页签 8px。
- **卡片不画线边框**：`GsCard` = 白底 + 1px 环（rgba 3.5%）+ 柔和投影（`--gs-shadow-float`），10px 圆角；表单输入、弹窗仍用 1px `--gs-border`；分割线 `--gs-divider`。
- 阴影只用 float（卡片/工具栏）、xs、modal 三档；页头插画允许一层品牌色 drop-shadow，不使用其它彩色光晕。

## 5. 色彩

- 主色：#335CFF（hover #3559E9）；语义色：success #1A7544、warning #B75310、error #D02533。
- 中性灰阶：文字 #171717 / #5C5C5C / #7B7B7B；背景 #FFFFFF / #F7F7F7 / #F5F5F5。
- **状态色只允许出现在 Tag、Alert、趋势数字**；其余界面保持中性。
- 深色主题同结构，值见 `GS_BRAND.dark`。

## 6. 表格（企业级数据页的核心）

- `GsTable`：`size="middle"`，表头 12/500 + `--gs-table-head` 底，行高 48，hover 浅灰，无外框。
- 首列为主信息（公司/线索名，14/500）；数字列右对齐 + tabular-nums；状态列用 `GsTag`。
- 空态统一 `GsEmpty`；加载统一 `a-skeleton`；分页默认 20/页，超过 50 条显示总数。

## 7. 表单

- label 上置（12/500），控件高 40，错误 12px 语义红（`a-form-item` 自带）。
- 同一行最多 2 个控件；主提交与次操作分列右侧（Modal 页脚右对齐）。

## 8. 反馈与弹层

- 成功：`feedback.message.success`（3s 自动消失）。
- 可恢复失败：`feedback.message.error`；页面级持久错误：`ErrorNotice`（a-alert，保留「发生了什么/为什么/怎么办 + 技术详情」三层）。
- 确认：`feedback.modal.confirm`；行内危险操作 `a-popconfirm`。
- 顶部通知：`feedback.notification.*`（暗色自动取 token）。
- Modal：10px 圆角，页脚右对齐「取消 / 确认」，危险操作用 `danger`。
- 接口没有三层文案时（网关 5xx、断网、超时、引擎透传的裸报错），按状态码给本语言的说明（`gainos.errors.*`，5xx 带状态码），
  英文原文只进「技术详情」，不当标题。规则在 `apps/web/src/api/failure-copy.ts`，页面报错块和右上角的全局提示共用（2026-11-26）。
- 按钮式的操作结果（如「从档案生成事实草稿」）用轻提示；随后的列表刷新原地更新，不进加载态。

## 9. 动效

- ≤150ms，只动颜色/透明度/阴影；禁止位移、缩放、弹跳。
- 加载态用骨架屏；列表进入不加动画。

## 10. 可访问性与测试锚点

- 保留语义：H1/H2 层级、`role=dialog/alert/status`、`role=tab` 顺序与文案、`aria-pressed`、`<main>`。
- 测试锚点统一 `data-gs="<area>"`（如 `data-gs="lead-card"`、`data-gs="queue-toolbar"`）；
  旧的 `.wk__*/.ld__*/.cp__*` 等页面类名不保留。
- 错误三层块必须保留 `.error-notice__details summary` 的「技术详情」折叠（既有 spec 依赖）。
- 复制到剪贴板统一走 `apps/web/src/utils/clipboard.ts` 的 `copyText`：用内网 IP 或 http:// 打开时浏览器不提供
  `navigator.clipboard`，直接调用会静默失败；`copyText` 会退回老办法，仍失败时抛错，由调用方提示用户（2026-11-26）。

## 11. 判定结果（C1–C5）的展示契约（2026-11-23）

引擎把五维评分写成一段聚合文本（`judge-aggregate/v1：verdict=…，reasonCodes=…` + `C1_MATERIAL pass（score 8）：…`）。
**这段原文只能进「技术详情」，租户界面一律渲染解析后的业务语言。**

- 解析：`apps/web/src/views/leads/judge.ts`（`parseJudge`）。维度顺序 C1→C5，分数 0–10，`null`=证据不足；
  兼容字符串、字符串数组、JSON 字符串与对象包装；解析失败时退回「机器结论 + 人话理由」。
- 文案：维度名 `gainos.leads.criteria.*`（产品品类 / 买家角色 / 生产工艺 / 经营模式 / 企业规模），
  状态走 `@gain-saas/shared` 的词表（符合 / 偏弱 / 不符 / 证据不足 / 不适用）。
  模型理由里的 `ICP` 用 `humanizeRationale()` 换成「买家画像」。
- 列表卡（`views/leads/lead-card.vue`）：公司（首字母牌位 + 国家/域名 + 行业/规模）→ 评分（分数 + 分档）
  → 判断结果/原因（决定性维度的一句话）→ 五维摘要（图标 + 结论 + 分数）→ 操作（值得跟进/暂不跟进/⋯）。
  「待我判断」的卡片用 3px 左侧强调条；展开后显示逐维理由，机器码只出现在折叠的「技术详情」。
- 详情（`views/leads/detail.vue`）：判断结果 hero（总分 + 分档 + 状态 + 维度计数 + 关键理由 + 核心证据）
  + 五维雷达（`GsRadar`，纯 SVG）+ 逐维明细（状态、0–10 分条、理由）。
  证据不足的维度按 0 绘制并在图下注明；`scores` 的八维明细作为补充卡片保留。
- 红线：`C1_MATERIAL`、`reasonCodes`、`judge-aggregate`、裸枚举不得出现在可见文本中
  （`leads-judge.spec.ts` 用真实形状的数据锁定）。

## 12. 渐变页头、药丸页签与名录卡片（2026-11-24，参考商业名录页）

### 12.1 页头与步骤面板
- `GsPage`：H1 28/600 + 副标题 13px；无 `#actions` 时右侧画装饰插画，有操作按钮时不画（避免重叠）。
- 主链路步骤条用共用的 `GsSteps`，2026-11-26 起只在底部的进度浮窗里渲染（见 §18），页面里不再各放一条；
  **页面里不要直接用 antd `Steps`**。
- **步骤条不显示序号**（用户不知道「5」指什么）：已完成的步骤是对勾，当前步是「蓝底圆 + 白点」，还没走到的步骤是空心圆。
  antdv 给 item 传了自定义 icon 就会取消默认蓝底圆（`ant-steps-item-custom`），圆底由组件自己画。
- 步骤条只做进度指示时，`GsSteps` 会去掉 antdv 给每一步加的假按钮语义；进度浮窗里每一步可点，
  开 `selectable` 后是真正的按钮（`role=button`，当前步 `aria-current=step`）。
- 当前步统一由 `apps/web/src/composables/use-main-chain-progress.ts` 算：第 1 步看有没有确认过的公司档案，
  第 2 步看有没有生效中的买家画像，第 3–5 步用 `utils/acquisition-step.ts`（最新方案与最近一次寻源）。页面不用各算一份。

### 12.2 药丸页签（`GsSegmented`）
- 文字项 13/500 + 计数；选中项 = `--gs-accent-soft` 浅蓝药丸 + `--gs-accent-fg` 文字，无下划线。
- antdv 4.2.6 的 `Segmented` 选中态固定是「灰轨道 + 白滑块」且不可令牌化，`Tabs`/`Radio.Group` 也没有这个形态，所以它是设计系统自有的最小原语：
  `role="group"` + 一组 `aria-pressed` 的 toggle button，Tab 逐个聚焦、Enter/Space 触发。

### 12.3 工具栏
- `GsToolbar`：白色浮起面板，padding 8px 12px 8px 8px；左侧页签、右侧「买家画像下拉 / 搜索 / 页面操作」。
- 带放大镜前缀的搜索框必须包一层定宽 div（见 §1 的 layer 陷阱）。

### 12.4 线索卡（`views/leads/lead-card.vue`）
- 五列：公司（56px 首字母色块 + 名称 15/600 + 定位行 + 行业/规模标签）→ 评分（28/600 + 线索评分 + 分档药丸）→
  判断结果（结论药丸 + 一行原因 + 展开收起）→ 判定维度（图标 + 名称 + 结论 + 0–10 分）→ 操作（跟进 / 排除 / ⋯，垂直居中）。
- 结论药丸 = **机器结论**（值得跟进 / 偏弱 / 不建议跟进 / 待评估），不是队列名；队列由当前页签表达，卡片内不再重复。
- 按钮文案与队列名对齐：「跟进」→ 已移入「值得跟进」，「排除」→ 已移入「已排除」（i18n `leads.cardAccept` / `leads.cardReject`）。
- 折叠态只留一行原因，维度计数摘要和逐维理由在展开区。
- 操作区：值得跟进 / 暂不跟进（或提升为商机）+「查看档案包」+ ⋯。「查看档案包」是判断前要看联系人、证据的入口，放在卡片上
  （`data-gs="lead-package"`）；⋯ 里只留低频的「复制官网域名」。操作列最窄按两个判断按钮算，放不下时按钮换行（2026-11-26）。
- 断点：内容区 ≥ ~1200px（视口 ≥ 1512px）五列并排；以下四列 + 判定维度横排到底部；手机单列。

### 12.5 没有数据、不做假的部分
公司 logo 用首字母色块（接口无图）；「已核验」对勾、评分涨跌箭头、「解锁积分」在参考图里有，但本产品没有对应数据，一律不画。

## 13. 线索研判与联系渠道

> 文案：页签、标题及相关提示统一用「联系人」，不再叫「决策人」（2026-11-25 产品负责人要求）。路由参数 `?tab=people` 与组件名 `DecisionMakerCard` 不变。

- 「研判」模式在宽内容区把候选、判断摘要、五项判据与证据放在同一页。使用原有队列和判断动作。窄内容区以候选列表打开 `GsDrawer`，宽度为 `min(520px, 100vw)`。表格和卡片供不同密度的扫描操作。
- 「联系人」页签使用整页内容区。企业公开渠道面向普通成员和管理员，个人渠道由已有管理员权限控制。人物卡先显示姓名、岗位和所属渠道入口，渠道入口把焦点移到对应信息卡。来源和日期按现有归属显示。
- 渠道卡由实际数据生成。企业层支持返回的职能邮箱、电话、询盘入口和公开资料链接。个人层展示该联系人关联的联系点，每个值并列显示核验状态、核验日期与可用操作。缺少头像时用姓名首字母，缺少的渠道无需占位。
- 已核验用绿色，待确认与推断使用琥珀色，拦截用红色，未验证和无效使用中性色。待确认或推断邮箱的验证仍走现有确认流程。具名资料来源没有渠道级归属时展示在人卡末尾。
- 卡片按内容区自适应换行。站外链接的用途由所在渠道和可读地址说明。 [W3C 链接用途](https://www.w3.org/WAI/WCAG22/Understanding/link-purpose-in-context.html)

## 14. 买家画像页（原「找买家」：买家画像 + 寻源方案，2026-11-25）

与买家线索页同一套「列表 → 详情」的结构，业务逻辑不变。

### 14.1 列表
- 页头、工具栏（标题 + 生效提示 / 刷新 / 设定买家画像）。步骤条在底部进度浮窗里（§18），页面里不再放。
- 画像卡（`views/find-buyers/icp-card.vue`）五列：画像（首字母色块 + 名称 + 公司 · 版本 + 状态药丸 + 规则数 / 对接角色数）/
  目标市场 / 寻源方案 / 最近寻源 / 操作（查看与调整）。
- 「寻源方案」「最近寻源」进入页面时按画像并行预取：取不到显示「—」，确实没有才显示「还没有」——
  不把「没取到」显示成「还没有」。预取不阻塞列表。
- 断点：视口 ≥ 1408px 五列并排（五列最少约 1070px 内容宽度）；以下两行（画像 + 操作 / 目标市场 + 寻源方案 / 最近寻源）；手机单列。

### 14.2 画像工作区（2026-11-26 修订：抽屉改页内）
- 画像列表在上，选中的画像在下方的工作区（`data-gs="icp-workspace"`）里展开，和公司档案的页内工作区同一形态，不再用右侧抽屉。
  工作区常驻：进页面默认展示生效中的画像（没有就取第一份），多份画像时头部有「切换画像」；从画像卡点进来会滚到工作区。
- 工作区分区（`section.fb-section`，标题 h3）：生效前只有「画像概览」（和反馈建议）；生效后「寻源方案」「最近寻源」排在前面，
  因为这时用户要做的是确认方案、发起寻源。概览内容：目标市场、目标公司属性、画像依据、五个板块、该找的人。
- **下一步**（`data-gs="icp-next"`）：贴在视口底部的横条，左边「下一步：做什么」加一行说明，右边一个「下一步」按钮。
  按状态只给一个动作：没激活 → 激活；生效后没方案 → 生成方案；方案待确认 → 确认；可执行 → 开始寻源；寻源在跑 → 看进度；
  已产出线索 → 去判断；没跑成 → 再跑一次。方案里原来的具体按钮保留，和「下一步」做同一件事（按钮名不同，不会重名）。
  数据在加载或出错时不显示，避免给错引导。实现是 `position: sticky; bottom: 12px`，元素放在页面根节点最后。
- 「高级：资格规则与回测」用 `ICP_ADVANCED_HIDDEN` 隐藏（`feature-flags.ts`）；画像卡上的规则数、新建说明里提到规则与回测的措辞一并隐藏。
- 画像卡（`icp-card.vue`）当前选中的加一圈浅蓝描边；没生效的画像，「寻源方案」「最近寻源」两栏写「先激活买家画像」，不写「还没有」。

### 14.3 寻源方案、编辑与弹层
- 方案先给结论：一句话「去 N 个渠道找，一共 M 组搜索，预计约 X 家，费用约 Y」，下面按来源渠道分组（`planGroups`）；
  搜索词默认收起，点「看搜索词」展开该渠道（关键词标签、国家或行业等筛选、给人看的说明）。
- 引擎写在搜索条件旁的说明常混着内部代码（`SOURCE_QUERY_BUDGET`、`icp_seed_gap`、CPV crosswalk）。`splitRationale` 把它按
  「；」「。」拆成小句：`icp_fit_warning:` 去掉前缀换成「注意」留在正文，其余带代码的小句收进「技术详情」，不带代码的照常展示。
  整份方案的原始 JSON 仍在折叠的「原始数据」里。
- 编辑画像是表单：名称、目标市场、五个板块（每项一行）；目标公司属性按已登记的字段逐个填（`ATTRIBUTE_FIELDS`，列表类一项一行），
  没登记的属性、嵌套结构和引擎写入的输入血缘字段收在最后的「其他属性（原始数据）」里。保存时保持原来的类型：
  原来是字符串、只填了一项的仍是字符串，不会把 `"US"` 变成 `["US"]`。
- 新建 / 规则仍是 antd `Modal`；操作结果走 `feedback.message`，不再在页面里挂固定提示条。
- 新建时选择公司档案只显示名称：公司状态没有业务词表，不显示原始枚举。

## 15. 响应式（2026-11-25）

### 15.1 三种导航形态
| 视口宽度 | 导航 | 内容区宽度 |
|---|---|---|
| < 768px（手机） | 左侧抽屉（汉堡按钮打开） | 视口 − 页边距 |
| 768–1023px（平板竖屏） | 侧栏自动收成图标窄栏（60px），可手动展开 | 视口 − 60 − 页边距 |
| ≥ 1024px | 按用户的展开/折叠偏好 | 视口 − 224 − 页边距（展开时） |

- 手机抽屉与桌面侧栏是同一份内容（`sdr-nav-panel.vue`）：分组导航 + 通知 / 设置 / 帮助 + 带退出登录的账号卡；
  抽屉品牌行额外放主题 / 语言切换（手机上原本没有入口）。
- 平板自动收起不改动用户的真实偏好：自动收起时在本地留标记，离开这个宽度时恢复（刷新过也恢复）；
  用户在平板宽度下手动展开视为明确选择，不再恢复（`layouts/basic.vue`）。

### 15.2 布局断点按内容区宽度，不按视口
侧栏展开 / 收起 / 变成抽屉都会改变内容区宽度，按视口设断点会在平板上排错（实测 224px 侧栏下 596px 的内容区按 820px 排版，右侧整列被裁掉）。

- 页面根节点统一写 `grid-cols-1 @container`：`grid-cols-1` 约束列宽（子内容再宽也不会把整列撑出屏幕），`@container` 让后代可以按内容区宽度查询。
- 组件样式窄屏优先，用 `@container (min-width: …)` 逐级变宽；模板里的工具类用 `@min-[…]:` / `@max-[…]:`。
- **不要按视口写断点**（`@media (max-width)`、`lg:` / `md:`），除非元素在 Teleport 出来的弹层里（弹层不在容器内，只能按视口）。
- 页面根加了 `@container` 后会成为 `position: fixed` 后代的包含块，所以页面内不要直接放 fixed 元素，弹层一律用 antd（Teleport 到 body）。

### 15.3 各组件的分档（数值是内容区宽度）
| 组件 | < 520 / 560 | 中档 | 最宽档 |
|---|---|---|---|
| 线索卡 `lead-card` | 单列堆叠 | ≥ 520 两列（评分 / 判断结果）；≥ 810 四列 + 维度横排 | ≥ 1180 五列 |
| 画像卡 `icp-card` | 单列堆叠（< 560） | ≥ 560 两列 | ≥ 1120 五列 |
| 联系人卡 | 三段竖排（< 860） | — | ≥ 860 三列对齐 |
| 线索详情网格 | 单列 | ≥ 760 两列；≥ 900 结论 + 雷达并排 | — |
| 主链路步骤条 `GsSteps` | 竖排（< 760，组件自己量容器） | — | 横排 |
| 工具栏 | ≥ 两个控件时各占一半宽，两两成行（< 640） | 自动换行 | 同行 |

- 窄屏优先意味着每档的最小宽度都算上卡片内边距（24×2）；新增卡片时先写堆叠形态，再往上加档。
- 图表（雷达图）限定最大宽度并居中，不要跟着单列堆叠的卡片拉满。

## 16. 公司档案：主档案 + 关联公司（2026-11-25）

### 16.1 产品口径
- 引擎/PRD（`phase-1-01-04` §2）允许**一个工作空间多份公司档案**（集团/多品牌），每份独立维护 Claim/Offering/ICP；
  引擎侧没有「主档案」概念，只有 BFF 的 `Workspace.onboardingCompanyId` 记录注册时填写的那家公司。
- 产品层因此显式引入「主档案」：**注册公司永远是主档案**，日常操作与寻源以它为准；其他档案收在「关联公司」，
  添加前必须说明用途（集团/多品牌），避免用户把它当成「随便再建几家公司」。
- 老工作空间没有 onboarding 记录时，回退到创建时间最早的一份，徽标显示「主档案」（不谎称注册公司）。

### 16.2 页面结构
- 页头（`GsPage` 渐变）+ 主档案卡：
  - 身份：首字母方块 + 公司名 + 「注册公司」徽标 + 状态药丸 + 官网/行业/目标市场；
  - KPI：已通过事实 / 待确认事实 / 产品服务 / 待处理冲突（`/companies/:id/completeness`，并行预取）；
  - 「下一步」：按状态与事实进度只给一个明确动作（补全 → 确认事实 → 处理冲突 → 设定买家画像），
    不再让用户自己在一排按钮里找；
  - 页脚：企业事实 / 资料库 / 编辑（仅 DRAFT）/ 更多（市场候选、重试理解、确认档案）+ 买家画像摘要（组数、生效中）。
- 关联公司：仅在存在其他档案时出现；每张卡显示状态、行业/市场、画像摘要与主操作；搜索/筛选只在关联档案 > 3 时出现。
- 「添加关联公司」是次级操作，先弹说明再进入建档。

### 16.3 与下游的衔接
- 「找买家 → 设定买家画像」的公司选择器把主档案排在第一位并标注「（注册公司）」，避免选错公司导致寻源偏差。
- 公司页在从其他页签返回（keep-alive 激活）时刷新画像与事实计数。

### 16.4 页内工作台（2026-11-25 修订）
- 建档、编辑、添加关联公司说明仍用 antd `Modal`。
- **企业事实、资料库不再用弹窗**：主档案卡下方是一块常驻工作台，包含当前档案选择器、刷新、事实/资料库分段视图。
  - 事实：左侧档案概览 + 冲突，右侧待确认/已通过/未采用清单与批量操作，一屏内完成判断与审批；
  - 资料库：左侧上传与文件清单，右侧资料检索；上传/解析/删除/检索都在页内完成。
- 主档案 KPI、页脚「企业事实/资料库」与关联公司卡入口都会切换视图并滚动定位到工作台；从关联公司进入时显示
  「返回主档案」，事实计数只对当前选中的公司生效，避免沿用上一家的数字。
- 「企业事实 / 资料库」分段视图不带计数：「企业事实 0」会被读成「没有事实」，其实那个 0 是待确认数。各状态的数量放在清单自己的
  页签上（待确认 / 已通过 / 未采用）。事实都审完、画像还没建时，主档案不再显示「下一步」标签和说明，只留「档案已就绪」和
  「设定买家画像」按钮（2026-11-26）。

### 16.5 页头识别
- `GsPage` 的 `art` 按页面语义提供不同插画与极浅底纹：买家线索=靶心/点阵，找买家=地球/同心圆，公司档案=楼宇/网格；
  不再让三个列表页共用同一张通用插画。设置类页面仍可用 `:hero="false"` 的素净页头。

## 17. 买家画像的用词（2026-11-26）

用户实测反馈：画像里的小标题读不懂（痛点、触发信号、排除条件、价值主张、买家委员会），「目标公司属性」里混着英文字段名，
「找买家」这个页面名也和它的内容对不上。

### 17.1 页面与概念
- 「目标客户画像」全站统一叫**「买家画像」**：页面与菜单标题、各页文案、共享词表（`glossary.ts` 的 `icp`、`NAV.findBuyers`、
  `terminology.ts`）一起改，不留第二个叫法。路由仍是 `/find-buyers`。
- 菜单里「买家画像」和「买家线索」同在「线索」分组；「获客」分组只剩「公司档案」。
- 「找买家」只在表示动作时保留（「开始找买家」「后续找买家」），不再当页面名。

### 17.2 画像的五个板块

| 原标题 | 现在 | 标题下的说明行 |
| --- | --- | --- |
| 痛点 | 客户难题 | 对方现在哪里不好办 |
| 触发信号 | 采购信号 | 出现什么迹象，说明对方准备买了 |
| 排除条件 | 不找的对象 | 什么样的公司直接跳过 |
| 价值主张 | 我们的卖点 | 我们能帮对方解决什么 |
| 买家画像（personas）/ 买家委员会 | 该找的人 | 这单采购要对接哪些角色 |

- 标题是名词，说明行解释这一栏问的是什么；详情和编辑表单用同一套。文案键 `findBuyers.<板块>` 与 `findBuyers.<板块>Hint`。
- `personas` 和 `buyingCommittee` 是引擎对同一批角色的两种写法，按职务合并成一张角色卡（想达成什么 / 客户难题 / 关注点）。
- 画像卡上的「N 个买家画像」原指角色数，改为「N 个对接角色」。
- 画像状态 `HYPOTHESIS` 的显示名由「假设」改为「待激活」。

### 17.3 目标公司属性与画像依据
- `companyAttributes` 是自由对象，键由模型给出。已登记的键走 `findBuyers.attribute.*`（中文名）；未登记的键原样显示键名，
  发现新的就补登记（本轮补了 `product` 产品、`trade_side` 交易角色）。
- `inputBasis` / `marketBasis` / `inputProducts` / `modelSuggestedMarkets` 不是目标公司的属性：它们是引擎写入的「输入血缘」，
  记录这份画像按什么生成。不计入目标公司属性，单独列成「画像依据」，值里的代码按 `findBuyers.lineageBasis` /
  `lineageMarket` 换成白话（`legacy_profile_floor` → 公司档案里的市场，等等）。
- 国家码按界面语言显示地区名（`utils/region-name.ts`），例如 US → 美国；查不到时原样显示代码。

## 18. 底部进度浮窗（2026-11-26）

用户建议：进度是跨页面的，不该绑在某个页面上。

- `components/gainos/flow-progress-bar.vue`，挂在 `layouts/basic.vue`，只在主流程页面渲染
  （`/companies`、`/find-buyers`、`/tasks`、`/runs`、`/leads` 及其子路径，`isFlowPath`）。工作台、设置、通知等页面不显示。
- 位置：`position: fixed`，贴内容区底部，高 40px，从侧栏右边开始（展开 224px、收起 60px，手机 0）；`z-index: 190`，
  在顶栏（200）和侧栏（201）之下、弹层之上。白底 + 顶部分割线 + 浮起投影，全部用 token，明暗自适应。
- 内容：`GsSteps selectable`，五步都能点。第 2、3 步都去买家画像页；第 4 步有最近一次运行时直达 `/runs/:id`，否则去任务列表。
- 收起：右侧按钮收成右下角一个小标签（「第 N / 5 步 · 当前步骤」），选择记在 `localStorage`（`gainos.flow-bar.collapsed.v1`）。
- 窄屏：浮窗宽度不足 760px（手机、侧栏展开的平板）时只显示一句「第 N / 5 步 · 当前步骤」，点开从底部展开成一列
  （盖在内容上，不占页面高度），选一步后收起。宽度监听要在根节点出现后再挂：根节点是 `v-if`，首次取到进度才渲染。
- 留白：浮窗一挂载就把高度写进根变量 `--gs-flow-bar-h`（不等进度数据，否则贴底的元素会先按没有浮窗摆放、等浮窗出来再跳一次；
  组件重新挂载时也靠这一次写入恢复；实例间计数，最后一个卸载才归零）。`gainos.css` 用它在路由视图容器末尾补一块占位
  （`[data-layout-region='scroll'] .page-route-container::after`）。另两个位置都试过、都不行（2026-11-26 实测）：
  加在滚动区的 `padding-bottom` 上，浏览器会把这段内边距算进贴底元素（`position: sticky` 的 `bottom`）的参照边，
  浮窗高度等于被扣两次；加在路由视图容器的 `padding-bottom` 上，容器高度固定、内容溢出时内边距不在内容后面，等于没加。
  买家画像页贴底的「下一步」用 `bottom: calc(12px + var(--gs-flow-bar-h))` 抬到浮窗上方；滚到页底时它回到页面里自己的位置。
- 命名：五步是「完善档案 / 设定买家画像 / 确认寻源方案 / 等待寻源 / 判断线索」。主流程页面上不要再放和某一步同名的按钮，
  否则读屏软件和按名称定位都分不清：页面内的新建入口叫「新建画像」，跨页跳转的叫「去买家画像」
  （`ux-round-2-flow-bar` 对每个主流程页面断言五个步骤名各只命中一个按钮）。
- 进度数据：`composables/use-main-chain-progress.ts`（模块级共享状态）。浮窗挂载时取数、每 30 秒刷新、页面路径变化时刷新；
  关键操作成功后页面调用 `notifyChainChanged()`（新建或激活画像、确认方案、发起寻源、确认档案、审批事实）。
  至少取到一次数据才显示，免得先画在第 1 步再跳。
