Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.
以 Awwwards、Webby Awards、FWA 获奖级网站为品质标准，完成后从排版、留白、视觉层级、色彩、动效、微交互、响应式和原创性上自检并持续优化，直到没有明显可提升之处。

## 用户友好设计准则

面向运营台、配置页和所有业务流程，先按以下顺序检查，再开始写界面。

1. **先给默认答案，再给控制权**
   - 常见选择做成预设卡片/默认值；用户只填系统无法推断的一项（例如只填 API Key）。
   - 地址、模型名、路由映射等能自动填的全自动填；高级参数折叠到「高级设置」，默认不出现。

2. **一次只问一件事**
   - 用向导或分步表单；首屏不出现内部概念（alias、base URL、priority、schema、探针）。
   - 内部术语必须暴露时，翻译成业务语言，并在旁边用一句人话解释“它影响什么”。

3. **系统承担推导、发现与校验**
   - 能自动发现的数据（模型列表、数据源、工作空间）自动拉取，让用户选择而不是手抄。
   - 保存前先测试；失败信息就近显示，并给出下一步（检查 Key / 换模型 / 重试），不要只抛 HTTP 状态码。

4. **能用选择就不用输入**
   - 模型、服务商、工作空间、来源从列表/卡片选；自由文本只用于系统确实无法枚举的内容。
   - 提供搜索/筛选，列表超过 10 项时不要只靠滚动。

5. **状态始终可见**
   - 当前默认值、连接状态、最近一次测试结果在页面上一眼可见。
   - 长任务显示“进行中/成功/失败”，禁止假成功；失败要说明发生了什么、为什么、怎么办。

6. **空状态是入口，不是终点**
   - 空态给 1 个主行动和少量示例（“选一个服务商开始”），不要只写“暂无数据”。
   - 首次使用给最短路径，完成后回到正常界面，不保留教学噪音。

7. **防错优先于报错**
   - 不可逆或高风险操作二次确认，并说明后果与可逆性。
   - 不合法提交在按钮上直接禁用并说明原因，不要等提交后报 400。
   - 删除前告知会连带删除什么；能撤销的给撤销。

8. **渐进披露，不删功能**
   - 高级能力保留但默认折叠；为简单让路，不为简单砍掉运维需要的能力。
   - 复杂配置提供“推荐配置”一键完成，同时保留手动覆盖。

9. **一屏一个主行动**
   - 每屏只有一个视觉最强的主按钮；次要操作弱化，危险操作单独颜色。
   - 避免同权重按钮堆叠；操作按使用频率排序。

10. **文案说人话**
    - 标题回答“要做什么”，说明回答“为什么/下一步”。
    - 首屏避免“上游/别名/路由/探针/结算”等实现词；用“服务商/模型/默认模型/测试连接”。

11. **可访问与响应式**
    - 对比度、键盘操作、焦点可见；移动端单列、触控目标不小于 40px。
    - 错误不只靠颜色表达，要有文字与图标。

12. **验收方式**
    - 让没看过文档的人独立完成主流程；记录点击次数和是否需要口头解释。
    - 主流程超过 3 步、或需要解释内部概念才能完成，即判定不合格，回到设计而不是加说明。

判断标准一句话：**运营不需要知道 new-api、模型别名或接口路径，也能把 AI 配好并看到成功。**

### 空状态补充（2026-11-22）

空态不再只给 1 条路径：给 **2–3 条真实可行的起步路径**（例如新建 / 导入 / 从上游转入），但视觉最强的主行动仍只保留一个。禁止只写“暂无数据”。

## 2026-11 视觉与交互基线

### 简单性原则

目标简单，设计简单，实现简单。砍掉标语、提示文字和次要标签；如果一个页面非得靠这些东西才看得懂，那就去改布局。每个决定都要同时提升客户体验（UX）、开发者体验（DX）和智能体体验（AX），而且不能弄坏任何东西。

- 适用范围：用户登录后的系统内页面；平台运营台 `/ops` 与登录/注册页不因视觉改造而动。
- 功能守恒：可以删除装饰性标语、重复提示与次要标签；表单标签、校验规则、错误/空状态、操作入口与 API 调用不得删除。
- AX：保留语义化标题、可读的控件名称与稳定测试锚点；不用视觉层级替代 DOM 语义。

### 布局与交互

- 侧边栏按 3 组业务分组（总览 / 获客与筛选 / 触达与转化）+ 底部「设置」直达整页入口；路由保持扁平，不新增多余层级路由。
- 首页 `/workspace` 是行动驾驶舱：今日摘要 → 阶段漏斗 → 行动清单（待办/已归档）→ 提醒（异常/机会/建议）→ 今日建议。
- 列表页统一「筛选区 + 表格/列表 + 空状态 2–3 路径」；详情页统一 `PageHeader`（24/500 + 16/24）。
- 设置统一收口为整页 `/settings/*` 单轨模式（已退役弹窗 `SettingsDialog`）：侧栏底部「设置」直达 `/settings/account`，由 `SettingsShell` 提供整页左侧分组子导航 + 右侧内容区（响应式 `@container` 窄屏自动转为顶部横向分段条），按角色动态展示子页（全员可见账号与空间、成员与角色；管理员额外可见禁联名单、数据来源、隐私与数据、审计日志、发信邮箱）。
